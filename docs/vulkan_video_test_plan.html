1. Executive Summary

1.1 What we are verifying

The hardware path: Blink VideoEncoder / VideoDecoder → Mojo → Vulkan{Encode|Decode}Accelerator → vkCmdEncodeVideoKHR / vkCmdDecodeVideoKHR → bitstream / decoded VkImage.

PropertyVerification method
Bitstream conformanceRe-decode with FFmpeg / JM / HM / aom + JVT / HM / Argon conformance checks
Visual qualityPSNR / SSIM / log-likelihood vs source YUV
Decoded-frame correctnessMD5 of VideoFrame planes vs golden checksum (when deterministic)
API conformancegtest VEA/VDA harness + WebCodecs WPT
StabilityASan / TSan / MSan, validation layers, 24-h soak, fault injection
Performance*_perf_tests + Tast perf wrappers
InteropWebRTC loopback, cross-decoder roundtrip
FallbackSynthetic fault injection in the factory

2. Testing Philosophy — Five-Tier Onion

Layered test strategy. A regression must reproduce at the lowest possible tier — that is the layer where a CL author can iterate fast.

3. Tier 1 — In-Process Unit Tests

Granularity: a single C++ class, mocked Vulkan dispatch table. Runtime: < 50 ms per test, < 30 s per binary. Where: media/gpu/vulkan/*_unittest.cc, in media_unittests.

15.1 Pre-launch quality gate

  • 7 consecutive days of green Tier 1–3 across all CQ lanes.
  • ≥ 95% JVT, ≥ 90% JCT-VC, ≥ 90% Argon pass rates on at least 2 vendors.
  • Perf regressions ≤ 5% vs VA-API baseline on ChromePerf dashboard.
  • Zero new validation-layer regressions.
  • One full 24-h soak passing.
