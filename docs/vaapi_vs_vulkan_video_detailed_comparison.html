4. DMABuf Export/Import <a name="dmabuf"></a>

VA-API DMABuf Export (from vaapi_wrapper.cc)

```cpp std::unique_ptr<NativePixmapAndSizeInfo> VaapiWrapper::ExportVASurfaceAsNativePixmapDmaBufUnwrapped( VASurfaceID va_surface_id, const gfx::Size& va_surface_size) {

// Must sync surface first! VAStatus va_res = vaSyncSurface(va_display_, va_surface_id);

// Export surface as DRM PRIME handles VADRMPRIMESurfaceDescriptor descriptor; va_res = vaExportSurfaceHandle( va_display_, va_surface_id, VA_SURFACE_ATTRIB_MEM_TYPE_DRM_PRIME_2, VA_EXPORT_SURFACE_READ_ONLY | VA_EXPORT_SURFACE_SEPARATE_LAYERS, &descriptor);

// Build NativePixmapHandle from descriptor gfx::NativePixmapHandle handle; handle.modifier = descriptor.objects[0].drm_format_modifier;

for (uint32_t i = 0; i < descriptor.num_layers; ++i) { // descriptor.objects[].fd are owned by caller // descriptor.layers[] describes each plane handle.planes.emplace_back( layer.pitch[0], layer.offset[0], 0, base::ScopedFD(descriptor.objects[object_index].fd)); }

// Create NativePixmapDmaBuf auto pixmap = base::MakeRefCounted<gfx::NativePixmapDmaBuf>( va_surface_size, si_format, std::move(handle));

return exported_pixmap; } ```

Vulkan Video DMABuf Export (equivalent)

```cpp // Export VkImage memory as DMABuf FD VkMemoryGetFdInfoKHR get_fd_info = { .sType = VK_STRUCTURE_TYPE_MEMORY_GET_FD_INFO_KHR, .memory = image_memory, .handleType = VK_EXTERNAL_MEMORY_HANDLE_TYPE_DMA_BUF_BIT_EXT, }; int dmabuf_fd; vkGetMemoryFdKHR(device, &get_fd_info, &dmabuf_fd);

// Get image subresource layout for plane offsets/strides VkImageSubresource subresource = {VK_IMAGE_ASPECT_PLANE_0_BIT, 0, 0}; VkSubresourceLayout layout; vkGetImageSubresourceLayout(device, image, &subresource, &layout); // layout.offset, layout.rowPitch give plane 0 info // Repeat for plane 1 with VK_IMAGE_ASPECT_PLANE_1_BIT ```

DMABuf Import (Creating surface from external buffer)

```cpp // VA-API: vaCreateSurfaces with VA_SURFACE_ATTRIB_MEM_TYPE_DRM_PRIME_2 // Already shown above

// Vulkan Video: Import DMABuf as external memory VkExternalMemoryImageCreateInfo ext_mem_info = { .sType = VK_STRUCTURE_TYPE_EXTERNAL_MEMORY_IMAGE_CREATE_INFO, .handleTypes = VK_EXTERNAL_MEMORY_HANDLE_TYPE_DMA_BUF_BIT_EXT, }; // Add to image create info pNext chain

5. Synchronization Mechanisms <a name="synchronization"></a>

VA-API Synchronization

VA-API uses implicit synchronization for most operations:

```cpp // From vaapi_wrapper.cc - synchronization points:

// 1. vaSyncSurface() - Wait for decode to complete bool VaapiWrapper::SyncSurface(VASurfaceID va_surface_id) { VAStatus va_res = vaSyncSurface(va_display_, va_surface_id); // Blocks until surface is ready return va_res == VA_STATUS_SUCCESS; }

// 2. vaMapBuffer() - Implicitly syncs on Intel drivers // From comments in code: // "vaSyncSurface() is not necessary on Intel platforms as long as // there is a vaMapBuffer() like in ScopedVABufferMapping"

// 3. Before export - MUST sync // ExportVASurfaceAsNativePixmapDmaBufUnwrapped(): VAStatus va_res = vaSyncSurface(va_display_, va_surface_id); va_res = vaExportSurfaceHandle(...);

// 4. Between contexts - SHOULD sync // From vaapi_jpeg_encode_accelerator.cc: // "We should call vaSyncSurface() when passing surface between contexts" if (!vpp_vaapi_wrapper_->SyncSurface(va_surface_id_)) { return; } ```

Vulkan Video Synchronization

Vulkan requires explicit synchronization:

```cpp // 1. Semaphores - GPU-GPU sync VkSemaphore decode_complete_semaphore; vkCreateSemaphore(device, &semaphore_info, nullptr, &decode_complete_semaphore);

// 2. Fences - CPU-GPU sync VkFence decode_fence; vkCreateFence(device, &fence_info, nullptr, &decode_fence);

// 3. In decode command recording: VkVideoBeginCodingInfoKHR begin_info = { .sType = VK_STRUCTURE_TYPE_VIDEO_BEGIN_CODING_INFO_KHR, .videoSession = video_session, .videoSessionParameters = session_params, // Reference slots for DPB }; vkCmdBeginVideoCodingKHR(cmd_buffer, &begin_info);

// Submit decode vkCmdDecodeVideoKHR(cmd_buffer, &decode_info);

// End coding scope VkVideoEndCodingInfoKHR end_info = {...}; vkCmdEndVideoCodingKHR(cmd_buffer, &end_info);

// 4. Submit with synchronization VkSubmitInfo submit_info = { .sType = VK_STRUCTURE_TYPE_SUBMIT_INFO, .waitSemaphoreCount = num_wait_semaphores, .pWaitSemaphores = wait_semaphores, .pWaitDstStageMask = wait_stages, .commandBufferCount = 1, .pCommandBuffers = &cmd_buffer, .signalSemaphoreCount = 1, .pSignalSemaphores = &decode_complete_semaphore, }; vkQueueSubmit(video_queue, 1, &submit_info, decode_fence);

// 5. Wait for completion (CPU side) vkWaitForFences(device, 1, &decode_fence, VK_TRUE, UINT64_MAX); ```

Sync Comparison Table

Scenario VA-API Vulkan Video
Wait for decode vaSyncSurface() vkWaitForFences() / semaphore wait
Before export vaSyncSurface() Fence or semaphore
Cross-context vaSyncSurface() Timeline semaphores
Pipeline barrier N/A (implicit) vkCmdPipelineBarrier()
Memory barrier N/A (implicit) VkMemoryBarrier
DMA sync Implicit VK_ACCESS_HOST_READ_BIT barrier

6. Protected Content (DRM) <a name="protected-content"></a>

VA-API Protected Content (from vaapi_video_decoder_delegate.cc)

```cpp // 1. Create protected session bool VaapiWrapper::CreateProtectedSession( EncryptionScheme encryption, const std::vector<uint8_t>& hw_config, std::vector<uint8_t>* hw_identifier_out) {

// Create protected config VAConfigID va_protected_config_id; vaCreateConfig(va_display_, VAProfileProtected, VAEntrypointProtectedContent, attribs, num_attribs, &va_protected_config_id);

// Create protected session VAProtectedSessionID va_protected_session_id; vaCreateProtectedSession(va_display_, va_protected_config_id, &va_protected_session_id);

// Attach to decode context vaAttachProtectedSession(va_display_, va_context_id_, va_protected_session_id);

return true; }

// 2. Per-frame encryption setup (from delegate) ProtectedSessionState SetupDecryptDecode( bool full_sample, size_t size, VAEncryptionParameters* crypto_params, std::vector<VAEncryptionSegmentInfo>* segments, const std::vector<SubsampleEntry>& subsamples) {

// Set encryption type (CENC CTR or CBC) crypto_params->encryption_type = ctr ? VA_ENCRYPTION_TYPE_SUBSAMPLE_CTR : VA_ENCRYPTION_TYPE_SUBSAMPLE_CBC;

// Fill segment info for each subsample for (const auto& entry : subsamples) { VAEncryptionSegmentInfo segment_info = {}; segment_info.segment_start_offset = offset; segment_info.segment_length = entry.clear_bytes + entry.cypher_bytes; memcpy(segment_info.aes_cbc_iv_or_ctr, iv.data(), 16); segment_info.init_byte_length = entry.clear_bytes; segments->push_back(segment_info); }

// Copy wrapped key memcpy(crypto_params->wrapped_decrypt_blob, hw_key_data_map_[key_id].data(), 16);

return ProtectedSessionState::kCreated; }

// 3. Submit encrypted buffer // Encryption params submitted as additional VABuffer vaCreateBuffer(va_display, va_context_id_, VAEncryptionParameterBufferType, sizeof(VAEncryptionParameters), 1, &crypto_params, &enc_params_buffer_id); ```

Vulkan uses Protected Memory extensions:

10. Integration Challenges <a name="challenges"></a>

1. Synchronization Model Change

Challenge: VA-API uses implicit sync; Vulkan requires explicit sync.

Solution:

  • Use VkFence for CPU waits (equivalent to vaSyncSurface)
  • Use semaphores for GPU-GPU sync
  • Implement proper barrier management

2. Session Parameters (SPS/PPS)

Challenge: VA-API submits SPS/PPS per-frame; Vulkan caches in session parameters.

Solution: ``cpp // Track active SPS/PPS IDs // On SPS/PPS change: vkUpdateVideoSessionParametersKHR(device, session_params, &update_info); // Or recreate session parameters if needed ``

3. DPB Management

Challenge: Vulkan requires explicit DPB slot management.

Solution:

  • Implement DPB slot allocator
  • Track reference frame states
  • Map H.264/H.265 DPB semantics to Vulkan slots

4. Memory Management

Challenge: Vulkan requires explicit memory allocation/binding.

Solution:

  • Use existing Chromium GPU memory allocator
  • Implement proper memory type selection for video
  • Handle device-local vs host-visible requirements

5. VP8 Support Gap

Challenge: Vulkan Video has no VP8 extension.

Solution:

  • Keep VA-API for VP8 (if needed)
  • Or use software decode for VP8
  • VP8 usage is declining (WebM → AV1)

6. Protected Content Complexity

Challenge: Different DRM approaches.

Solution:

  • Start with unprotected content
  • Add protected memory support in phase 2
  • May need platform-specific CDM integration

7. Driver Maturity

Challenge: Vulkan Video drivers are newer than VA-API drivers.

Solution:

  • Test on multiple vendors (NVIDIA, AMD, Intel)
  • Implement fallback to VA-API
  • Report driver issues upstream

Summary

Key Takeaways

  1. Parsing is the same: Chromium's codec parsers (H264Decoder, etc.) are fully reusable.
  1. Major difference is control model: VA-API = implicit, Vulkan = explicit.
  1. DMABuf interop is similar: Both support DRM PRIME / DMABuf export/import.
  1. Synchronization needs attention: Must implement explicit fences/semaphores.
  1. Session parameters are different: Vulkan caches SPS/PPS in session params object.
  1. Protected content needs work: Different approaches require careful mapping.
  1. Frame output path is reusable: MailboxVideoFrameConverter works with any NativePixmap source.

Recommended Implementation Order

  1. VulkanVideoWrapper - Core API abstraction
  2. H264 unprotected decode - Most common codec
  3. H265 decode - Similar to H264
  4. DMABuf export/import - For compositor integration
  5. VP9/AV1 decode - As extensions become available
  6. Protected content - DRM support
  7. Encode support - Future phase
